## Grupo F — Checkbox visual para columnas booleanas (R19) ✅ (2026-09-22)

20. [x] `catalogo_live.ex`, `celda_body/1` (cláusula `tipo_columna: :negocio`)
    — chequea `schema_context_properties["tipo"] == "boolean"`; si es así,
    renderiza `<input type="checkbox" checked={@valor == true} disabled
    class="checkbox checkbox-sm" />` en vez de llamar `formatear_celda/2`
    — `nil` cuenta como desmarcado, igual que `false` (ver `02.design.md`
    §6).
21. [x] `meta_fixture_cliente` (catálogo de test compartido, 35 archivos
    lo usan) — se le agregó un campo booleano real
    (`meta_fixture_cliente_activo`) vía el mecanismo real de BC Motor
    (`MetaSchemaContext.agregar_detalle/2` + `CatalogoGenerador.generar/1`,
    replicado en dev Y test por separado) para poder probar R19 con un
    catálogo real, no un mock. **Hallazgo real en el camino**: el campo
    nuevo quedó REQUERIDO por default (`opcional` faltante en el
    `.meta.json`) — reventó 107 tests existentes que ya creaban filas de
    este fixture sin ese campo. Corregido marcándolo `"opcional": true`
    (dev y test) y regenerando — `mix test` completo volvió a 702/704 (2
    fallas preexistentes de siempre, sin relación).
22. [x] `test/metadata_app_web/live/catalogo_live_booleano_test.exs`
    (3 tests, LiveView real montado, sin mock) — `true` se pinta marcado,
    `false` desmarcado, ninguno de los dos casos deja el texto
    "true"/"false" en la celda, y el checkbox siempre tiene `disabled`.
23. [x] `mix test` completo: 702/704 (2 fallas preexistentes, mismas de
    siempre) — limpio respecto a los cambios de hoy.
24. [x] **Segundo hallazgo real, reportado por el usuario contra un
    catálogo real** (`pty_sat_usocfdi`, campo `es_moral`, después de
    desplegado): el checkbox quedaba invisible en pantalla — capturas
    reales confirmaron datos y metadata correctos (`true`/`false`
    reales, `"tipo": "boolean"` bien seteado), descartando un problema
    de datos. Causa real: `class="checkbox checkbox-sm"` (daisyUI) no
    se ve en esta app — este proyecto evita daisyUI a propósito
    (`AGENTS.md`). Corregido a las mismas clases planas de Tailwind que
    ya usa, en la misma tabla, el checkbox de selección de fila
    (`rounded border-gray-300 text-purple-600`) — visible confirmado
    (mismo patrón ya en uso en esa página). `02.design.md` §6
    actualizado con la corrección. Los 3 tests de
    `catalogo_live_booleano_test.exs` no dependían de la clase CSS
    (revisan `type="checkbox"`/`checked`/`disabled`), siguieron en
    verde sin cambios.
25. [x] **Tercer hallazgo real, mismo día**: pedido de pintar el
    checkbox azul — `text-blue-600` compiló bien en el CSS pero no
    cambió nada visualmente (seguía negro nativo). Causa: `text-*` solo
    controla el color de un checkbox nativo con el plugin
    `@tailwindcss/forms` cargado, que este proyecto NO tiene — ni
    siquiera el checkbox de selección de fila (mismo `text-purple-600`)
    se veía morado nunca, solo nadie lo había notado. Corregido a
    `accent-blue-600` (utilidad `accent-color` propia de Tailwind, sin
    plugin) — confirmado en el CSS compilado (`priv/static/assets/css/app.css`)
    y visualmente por el usuario. `02.design.md` §6 actualizado.
