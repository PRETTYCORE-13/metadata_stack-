# SPEC-SYS-0909202601 — Framework de Navegación

**Documento:** Explicación general · **Fase:** ✅ aprobada (2026-09-09), con incrementos reales verificados después (2026-09-09/10 y 2026-09-18).

## ¿Qué problema resuelve?

Cualquier pantalla del sistema, una vez que iniciaste sesión, está
envuelta por el mismo marco fijo: una banda lateral con el árbol de
navegación, una banda superior con datos de la sesión, una banda
inferior con información de contexto, y un menú administrativo para
tareas que no son "de negocio" (cambiar tu unidad operativa, cerrar
sesión, entrar a pantallas de plataforma). Ese marco es el "framework
de navegación" — se arma una sola vez y lo reusa cada pantalla, en vez
de que cada una resuelva por su cuenta cómo se llega a ella o qué
acciones globales ofrece.

Esta spec documenta CÓMO se llega a cada pantalla y QUÉ hay siempre
disponible alrededor — nunca el contenido propio de cada pantalla del
menú (eso es responsabilidad de la spec de cada una).

## ¿Cómo funciona, a grandes rasgos?

El sidebar izquierdo muestra un árbol de carpetas colapsables, como un
explorador de archivos, armado a partir de todas las pantallas que
existen — pero podado: solo ves lo que tenés permiso de "leer", y una
carpeta sin nada visible adentro tampoco aparece. Podés buscar dentro
del árbol, colapsarlo a solo íconos, y ajustar su ancho arrastrando el
borde — todo eso se recuerda entre sesiones. Con el riel colapsado, una
carpeta de nivel raíz se abre como un panel flotante en vez de expandir
todo el riel.

Arriba, la topbar muestra la empresa activa, una campana de
notificaciones y tu usuario (solo informativo, no despliega nada). Todo
lo administrativo — Roles, Empresas, RBAC, Jerarquía organizacional, y
si sos sysadmin de plataforma también Credenciales, Ambientes de
Deploy, Panel de Control y Acciones externas — vive en un único menú
que se abre desde el ícono de engrane al pie del sidebar, con el mismo
estilo visual que el panel flotante de carpetas. Ese menú también
ofrece, siempre disponibles para cualquiera con sesión iniciada,
"Cambiar Unidad Operativa", "Configuración de cuenta" y "Cerrar
sesión" — nunca queda vacío, por eso el engrane siempre se muestra.

Abajo, el footer muestra el copyright, tu jerarquía operativa activa
(Empresa/Sucursal/Almacén/Unidad de Venta) de solo lectura, un botón
para copiar la ruta de la pantalla actual y un buscador directo por
TRN. En pantallas chicas (celular), tanto el sidebar como el footer se
ocultan por default y se revelan a demanda, para no comerse la
pantalla.

## Historia — una corrección real en vivo

El menú administrativo tuvo, el mismo día que se armó, dos correcciones
a pedido explícito: se sacó el segundo acceso que tenía desde tu
usuario en la topbar (quedó solo el engrane), y se rediseñó para verse
igual que el panel flotante de carpetas, en vez de un dropdown
distinto. Más adelante (2026-09-18) apareció un bug real: un usuario
sin ningún permiso administrativo se quedaba sin poder cerrar sesión ni
cambiar su contraseña, porque el engrane se ocultaba por completo si no
tenía ninguna opción de Sysadmin — se corrigió para que el engrane
siempre se muestre a cualquiera con sesión iniciada, ya que "Cambiar
Unidad Operativa"/"Configuración de cuenta"/"Cerrar sesión" siempre
están ahí.

## ¿Quién usa esta funcionalidad?

Todos: cualquier usuario autenticado ve y usa este marco en cada
pantalla del sistema. Lo que cambia persona a persona es cuánto del
árbol y del menú administrativo se le muestra, según sus permisos.

## Lo que esta spec NO hace

No documenta el contenido de cada pantalla del menú (BC List, Roles,
Jerarquía organizacional, etc. — cada una tiene su propia spec), ni el
mecanismo interno de permisos RBAC (esta spec solo lo consulta para
podar el árbol y el menú, no lo define), ni el detalle visual de
theming/CSS.
