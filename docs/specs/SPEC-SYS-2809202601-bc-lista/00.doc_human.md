# SPEC-SYS-2809202601 — BC Lista (lista de artefactos)

**Documento:** Explicación general · **Fase:** ✅ aprobada (2026-09-28).

## ¿Qué problema resuelve?

Todo lo que se construye en la plataforma —catálogos, consultas,
vistas SQL y las carpetas que los organizan en el menú— necesita un
lugar central desde donde verlo, encontrarlo y administrarlo. Esa
pantalla es **BC Lista** (en el menú de Sysadmin aparece como "BC
List"): el punto de partida para crear un artefacto nuevo, entrar a
editar uno existente, ordenarlos en el menú o mandarlos a otro
ambiente.

Hasta hoy esta pantalla no tenía una spec propia: fue creciendo con
cada funcionalidad nueva (copiar un catálogo, consultas, vistas SQL,
publicar), y cada una quedó documentada por separado. Esta spec la
describe completa en un solo lugar y, además, corrige un problema
real: **la pantalla se siente lenta**. Al abrirla, al buscar o al
cambiar de página, el sistema revisa uno por uno todos los catálogos
para saber si están listos para publicarse, aunque en ese momento
nadie vaya a publicar nada. Con 34 catálogos esa revisión ya tarda
casi medio segundo, se hace dos veces al entrar, y crece con cada
catálogo nuevo.

## ¿Cómo funciona, a grandes rasgos?

La pantalla muestra una tabla con forma de árbol, igual que el menú
de la aplicación: carpetas que se abren y se cierran, y dentro de cada
una sus catálogos, consultas y vistas SQL. De cada artefacto se ve su
nombre de sistema, su etiqueta, su ruta en el menú (con un botón para
copiarla), si está visible u oculto, y sus acciones: Editar, Copiar
(solo en catálogos simples) y Eliminar.

Arriba hay un buscador por nombre o etiqueta y la paginación (por
carpeta principal, para que una carpeta nunca quede partida entre dos
páginas). Junto a ellos están los botones para crear y organizar:

- **+ Carpeta** — crea un directorio que, al guardarse, aparece en el
  árbol de navegación del menú lateral.
- **+ Catálogo** — crea una transacción: alta, baja y cambio de
  datos, con su propia API para que otras integraciones la consuman,
  además de personalizaciones para el usuario.
- **+ Ecto** — crea una consulta indicando qué tablas usa como fuente
  de datos; el sistema arma la consulta automáticamente y permite
  personalizarla para el cliente (ordenamientos, totales por columna,
  ocultar campos, etc.).
- **+ SQL View** — crea una vista de la base de datos, para poner
  filtros especiales a un catálogo o armar reportes complejos para
  los usuarios.
- **Vista** — permite ordenar el árbol, acomodando los artefactos de
  negocio con arrastrar y soltar.

Cada catálogo que ya está completo y sin errores muestra una casilla
para marcarlo; con uno o más marcados aparece **Publicar paquete**,
que propaga esos artefactos de negocio juntos al sistema que se
elija: cualquiera de los sistemas dados de alta en la plataforma, o
`unstable` si se quiere una primera validación antes.

Con esta spec, la tabla aparece de inmediato y la revisión de "¿está
listo para publicarse?" se hace en segundo plano: las casillas de
publicar aparecen un instante después, sin detener lo demás. Buscar,
cambiar de página o abrir una carpeta deja de repetir esa revisión, y
solo se vuelve a hacer cuando algo cambió de verdad (se guardó,
creó, copió o eliminó un artefacto).

## ¿Quién usa esta pantalla?

Gente de ADN o del equipo de plataforma con acceso de Sysadmin a los
Business Contexts. No es una pantalla para el usuario final de
negocio.

## Lo que esta spec NO hace

No cambia cómo funciona cada acción que ya tiene su propia spec —
copiar un catálogo (SPEC-SYS-1809202602), la Consulta Ecto
(SPEC-SYS-2509202602), la SQL View (SPEC-SYS-2509202601), ni cómo
viaja un catálogo entre ambientes (SPEC-ARQ-2209202602)—; solo las
referencia. Tampoco cambia qué hace que un catálogo esté "listo para
publicarse": el criterio es el mismo, solo cambia cuándo se revisa.
