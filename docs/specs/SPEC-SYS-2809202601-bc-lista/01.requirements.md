# SPEC-SYS-2809202601 — BC Lista (lista de artefactos)

**Documento:** Requirements · **Fase:** ✅ aprobada (2026-09-28).

## 1. Propósito y alcance

BC Lista (`/sysadmin/bc-list`, "BC List" en el menú de Sysadmin) es la
pantalla central para ver, crear, ordenar, editar, eliminar y publicar
los artefactos de negocio: carpetas, catálogos, Consultas Ecto y SQL
Views. No tenía spec propia; cada funcionalidad que se le agregó quedó
documentada en su propia spec.

Esta spec tiene dos partes:

- **§2–§7, retroactivo:** describe el comportamiento que ya existe, para
  que sea el ancla de cambios futuros. No pide construir nada.
- **§8, incremento de rapidez (nuevo):** la carga de la pantalla hoy
  tarda 420–630 ms del lado del servidor (medido en dev el 2026-09-28,
  50 artefactos, 34 catálogos maestro) y crece con cada catálogo nuevo.
  Casi todo ese tiempo se va en revisar si cada catálogo está listo para
  publicarse, aunque nadie vaya a publicar en ese momento.

Lo que ya tiene spec propia solo se referencia, no se repite:

| Acción | Spec |
|---|---|
| Copiar un catálogo | SPEC-SYS-1809202602-copiar-bc |
| + Ecto (Consulta Ecto) | SPEC-SYS-2509202602-consulta-ecto |
| + SQL View | SPEC-SYS-2509202601-consulta-sql |
| Sistemas destino al publicar | SPEC-ARQ-0309202601-alta-sistema-nuevo |
| Cómo viaja un artefacto entre ambientes | SPEC-ARQ-2209202602-propagacion-artefactos-negocio |

## 2. Acceso

R1. EL SISTEMA DEBE mostrar BC Lista solo a usuarios con permiso de
lectura sobre `sysadmin_bc`.

## 3. Tabla en forma de árbol

R2. EL SISTEMA DEBE mostrar los artefactos como un árbol con la misma
estructura que el menú lateral: carpetas que se abren y cierran, y
dentro de cada una sus catálogos, Consultas y SQL Views.

R3. EL SISTEMA DEBE mostrar todas las carpetas cerradas al entrar.
Abrir o cerrar una carpeta no se recuerda entre visitas.

R4. EL SISTEMA DEBE mostrar de cada artefacto: nombre de sistema,
etiqueta (con la marca "Consulta" o "SQL View" cuando aplica), ruta de
navegación (con un botón para copiarla) y estado Visible/Oculto.

R5. EL SISTEMA DEBE mostrar por artefacto solo las acciones que le
aplican:
- **Editar**: en todos; lleva al editor que corresponde a su tipo
  (BC Motor para un catálogo, editor de Consulta o editor de SQL View).
  En una carpeta abre su formulario (R11).
- **Vista**: en cada carpeta raíz, para reordenar solo su contenido
  (R10).
- **Copiar**: solo en catálogos maestro simples, según los criterios de
  SPEC-SYS-1809202602 (no carpetas, no Consultas, no SQL Views, no
  detalles, no maestros con detalles).
- **Eliminar**: en todos, con las reglas de §6.

## 4. Búsqueda y paginación

R6. CUANDO el usuario escribe en el buscador, EL SISTEMA DEBE filtrar
por nombre o etiqueta, esperando 200 ms después de la última tecla, y
regresar a la página 1.

R7. CUANDO hay búsqueda, EL SISTEMA DEBE conservar las carpetas que son
ancestros de un artefacto encontrado, con su ícono y etiqueta reales, y
quitar las carpetas que quedan vacías, salvo que la carpeta misma
coincida por nombre.

R8. EL SISTEMA DEBE paginar por carpeta raíz (30 por página), nunca por
renglón, para que una carpeta siempre aparezca completa en una sola
página.

## 5. Crear y ordenar

R9. EL SISTEMA DEBE ofrecer los botones:
- **+ Carpeta**: crea una carpeta (etiqueta, carpeta padre, ícono,
  visible) que aparece en el árbol de navegación del menú lateral.
  Rechaza una ruta que ya use otro artefacto.
- **+ Catálogo**: lleva al asistente de catálogo nuevo.
- **+ Ecto**: ver SPEC-SYS-2509202602.
- **+ SQL View**: ver SPEC-SYS-2509202601.
- **Vista**: modo para reordenar el árbol con arrastrar y soltar.

R10. CUANDO el usuario suelta un artefacto o carpeta en modo Vista, EL
SISTEMA DEBE guardar de inmediato el orden completo de ese nivel, que
se refleja en BC Lista y en el menú lateral. Aplica también a carpetas
automáticas (las que existen solo por la ruta de un artefacto, sin
registro propio).

R11. EL SISTEMA DEBE permitir editar una carpeta (etiqueta, ícono,
visible) sin cambiar su ruta.

## 6. Eliminar

R12. CUANDO se pide eliminar un **catálogo**, EL SISTEMA DEBE revisar
primero su impacto:
- Si otros catálogos dependen de él, bloquear el borrado y mostrar
  cuáles son.
- Si no, pedir que se escriba el nombre exacto del catálogo antes de
  habilitar "Eliminar", mostrando cuántos registros se van a perder.

R13. CUANDO se elimina un catálogo `pty_*` o `demo100_*`, EL SISTEMA
DEBE ofrecer enseguida despublicarlo de un sistema elegido, porque ese
borrado no viaja por git.

R14. CUANDO se pide eliminar una **carpeta** que todavía tiene algo
adentro, EL SISTEMA DEBE rechazarlo, revisándolo al pedirlo y otra vez
al confirmar.

R15. CUANDO se pide eliminar una **Consulta** o **SQL View**, EL SISTEMA
DEBE pedir una confirmación simple. Una SQL View que algún campo usa no
se elimina (SPEC-SYS-2509202601).

## 7. Publicar paquete

R16. EL SISTEMA DEBE mostrar una casilla de selección en los catálogos
maestro listos para publicarse (completos, estructuralmente válidos,
con reglas sin error de sintaxis y compiladas) y en toda carpeta creada
con "+ Carpeta" (no tiene autómata que validar). Los detalles y las
carpetas implícitas nunca la muestran; los detalles viajan con su
maestro. **Corregido 2026-09-29** (SPEC-SYS-2909202601): el texto
anterior decía "solo en los catálogos maestro", pero el código ya
mostraba la casilla también en carpetas.

R17. CUANDO hay uno o más catálogos marcados, EL SISTEMA DEBE mostrar
"Publicar paquete (N)". Al abrirlo, muestra el paquete completo
(detalles y catálogos referenciados, en orden) y sus problemas antes de
tocar nada.

R18. EL SISTEMA DEBE pedir elegir el sistema destino, sin valor por
defecto: `unstable` o cualquiera de los sistemas dados de alta
(SPEC-ARQ-0309202601). "Publicar" queda deshabilitado mientras no se
elija.

R19. MIENTRAS el paquete se está publicando, EL SISTEMA DEBE mostrar el
progreso sin permitir cerrar el modal ni publicar dos veces, y mostrar
el error en el modal si algo falla.

## 8. Rapidez (incremento nuevo)

R20. **Nuevo 2026-09-28.** CUANDO el usuario entra a BC Lista, EL
SISTEMA DEBE mostrar la tabla sin esperar la revisión de "listo para
publicarse" (R16). Las casillas de selección aparecen cuando esa
revisión termina, sin bloquear el uso de la pantalla mientras tanto.

R21. **Nuevo 2026-09-28.** EL SISTEMA DEBE hacer la revisión de R16 una
sola vez por visita a la pantalla, no en la carga inicial y otra vez al
conectar.

R22. **Nuevo 2026-09-28.** CUANDO el usuario busca, cambia de página,
abre o cierra una carpeta, o marca una casilla, EL SISTEMA NO DEBE
repetir la revisión de R16 ni consultar la base para decidir si
mostrar "Copiar".

R23. **Nuevo 2026-09-28.** CUANDO se crea, copia o elimina un
artefacto desde BC Lista, o llega el aviso de que otro usuario creó o
cambió uno, EL SISTEMA DEBE volver a revisar R16 en segundo plano.

R24. **Nuevo 2026-09-28.** CUANDO el usuario abre "Publicar paquete",
EL SISTEMA DEBE volver a confirmar que cada catálogo marcado sigue
listo, y avisar cuál dejó de estarlo, porque pudo cambiar en otra
pestaña después de la última revisión.

R25. **Nuevo 2026-09-28.** CUANDO la revisión de R16 falla por un error
inesperado, EL SISTEMA DEBE mostrar la tabla igual, sin casillas de
selección, y avisar que no se pudo revisar si los catálogos están listos
para publicarse.

R26. **Nuevo 2026-09-28.** La mejora DEBE medirse contra la base de
dev con los mismos 50 artefactos: la carga de la tabla sin la revisión
de R16 debe quedar por debajo de 150 ms del lado del servidor, y
buscar o cambiar de página por debajo de 50 ms.

## 9. Fuera de alcance

- Cambiar qué hace que un catálogo esté "listo para publicarse" (el
  criterio de R16 se conserva igual, solo cambia cuándo se revisa).
- Acelerar la revisión de un catálogo en sí (`puede_desplegar?/1`); aquí
  solo se evita repetirla.
- La lentitud de la Ficha 360° (103 consultas por registro, medida el
  mismo día); queda para una spec aparte.
- Cambiar el respaldo a long-polling del navegador.
