## Nota — bug corregido tras el cierre (2026-09-25)

**Síntoma reportado por el usuario:** en dev ningún botón respondía (por
ejemplo, "Cancelar") después de guardar dos veces el SQL de una SQL View
(`pty_sql_test___salesuconfig`).

**Causa:** cada guardado generaba `<ts>_vista_<nombre>.exs`, con el
mismo **nombre** de migración en cada edición. Ecto exige nombres únicos
("migration name … is duplicated"), y `Phoenix.Ecto.CheckRepoStatus`
(endpoint de dev) revisa las migraciones en cada petición, así que las
pantallas fallaban. `mix test` tampoco arrancaba. No lo detectó la
verificación de B3, porque el Migrator dentro del proceso solo veía una
migración pendiente a la vez.

**Corrección:** `ConsultasSql.ruta_migracion/3` agrega el timestamp
también como sufijo (`<ts>_vista_<nombre>_<ts>.exs`, igual que
`crear_pty_x_<ts>` de los catálogos), y lo mismo para la de
eliminación. Los dos archivos que ya existían en dev se renombraron con
ese formato, con la misma versión (ya estaban aplicados, no se vuelven
a ejecutar). Test agregado en `consultas_sql_test.exs`. Verificado: los
dos "Cancelar" (modal "+ SQL View" y formulario "Filtros") cierran sin
guardar, y el servidor de dev responde de nuevo.
