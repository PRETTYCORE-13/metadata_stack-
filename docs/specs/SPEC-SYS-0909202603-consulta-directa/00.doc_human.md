# SPEC-SYS-0909202603 — Consulta Directa (diagnóstico de datos)

**Documento:** Explicación general · **Fase:** solo requirements, sin
diseño ni implementación todavía.

## ¿Qué problema resuelve?

Cuando un usuario reporta que "un registro no aparece", alguien del
equipo de soporte o consultoría necesita poder mirar la tabla real,
directo, sin depender de ninguna pantalla armada de antemano, para
confirmar si el registro existe de verdad y por qué no se le está
mostrando a ese usuario — la causa más común es que el Alcance de
Datos (la regla que filtra qué empresa/sucursal/almacén/unidad de
venta puede ver cada quien) lo está ocultando. Hoy no existe una
herramienta pensada para ese diagnóstico puntual: las pantallas
normales respetan el Alcance de Datos a propósito, que es justo lo que
hay que poder saltear para confirmar el diagnóstico.

Esta spec propone "Consulta Directa": una herramienta nueva, exclusiva
para ese perfil de soporte/consultoría, que deja mirar cualquier
catálogo tal cual está en la base — sin curar nada de antemano, sin
Alcance de Datos, e incluyendo si hace falta los registros dados de
baja — para diagnosticar, nunca para operar.

## ¿Cómo funciona, a grandes rasgos?

No hay que confundirla con **Reportes** (la función ya existente,
antes llamada "Consulta Ecto"), que es lo opuesto a propósito: un admin
arma de antemano qué columnas mostrar y cómo filtrar, pensada para que
un usuario de negocio la abra muchas veces, respeta RBAC y Alcance de
Datos, y se publica a producción. Consulta Directa, en cambio, sería
efímera: el consultor elige un catálogo cualquiera (con tabla física
propia), filtra por cualquier columna real —incluidas las de sistema
que Reportes no expone, como estado, sucursal o TRN—, y ve los
resultados tal cual están guardados, sin Alcance de Datos y, si lo
pide explícitamente, incluyendo registros dados de baja. Nunca se
guarda ni se publica como algo reutilizable: cada uso empieza de cero,
y es exclusivamente de lectura — nada se puede crear, editar ni borrar
desde ahí. Por el nivel de datos sensibles al que da acceso (cruzando
Alcance de Datos), requeriría un permiso propio, distinto a cualquier
permiso ya existente, para poder abrirla.

## Historia

Esta spec quedó documentada solo hasta el nivel de requirements — deja
explícito el problema, el alcance y las reglas de negocio esperadas,
pero todavía no se avanzó a diseñar cómo se construye ni a
implementarla.

## ¿Quién usa esta funcionalidad?

Cuando exista, sería exclusiva de un perfil de soporte/consultoría —
nunca de un usuario de negocio común, justamente porque salta el
Alcance de Datos que protege a los demás. El acceso quedaría acotado
por un permiso propio, separado de cualquier otro permiso del sistema.

## Lo que esta spec NO hace

Todavía no tiene diseño (`02.design.md`) ni lista de tareas
(`03.tasks.md`) — no hay código construido para esto. A pedido
explícito del usuario, tampoco modificaría nada de lo ya existente
(Reportes, `CatalogoLive`, RBAC, Alcance de Datos): todo lo que
necesite reusar lo consumiría tal cual está, y cualquier cambio a algo
compartido se conversaría antes, nunca se asumiría en silencio.
