# SPEC-SYS-2509202603 — Jerarquía organizacional

**Documento:** Design · **Estado:** documentación retroactiva del
diseño ya implementado. No hay decisiones técnicas nuevas en este
documento.

## 1. Modelo de datos

Cuatro tablas de sistema (mismo trato que otras tablas de plataforma:
no son catálogos generados por el Motor BC, no llevan prefijo `pty_`),
todas con baja lógica vía `delete_guid` y trazabilidad
`insert_guid`/`update_guid`:

```
meta_schema_empresa
  nombre

meta_schema_branch
  empresa_id (FK)
  branch_name

meta_schema_sales_unit
  empresa_id (FK)   -- denormalizado, ver R17
  branch_id (FK)
  sales_unit_name
  sales_unit_type    -- texto libre, no enum

meta_schema_inventory_location
  empresa_id (FK)   -- denormalizado, ver R17
  branch_id (FK)
  inventory_name
  inventory_type     -- texto libre, no enum
  inventory_function -- texto libre, no enum
```

Jerarquía: `Empresa -> Branch -> {SalesUnit, InventoryLocation}` —
estas dos últimas son **hermanas** bajo `Branch`, ninguna anidada
dentro de la otra.

Módulos Ecto: `MetadataApp.Autenticacion.{Empresa, Branch, SalesUnit,
InventoryLocation}` (`lib/metadata_app/autenticacion/*.ex`).
`sales_unit_type`/`inventory_type`/`inventory_function` son
intencionalmente texto libre (preventa/autoventas/pdv/call center;
planta/punto de embarque/almacén; comprometida/producto terminado/
producción, entre otros) — no son listas cerradas en el modelo actual.

## 2. Contexto (`MetadataApp.Autenticacion`)

CRUD simple por nivel, sin transacciones combinadas entre niveles
(a diferencia de `crear_empresa_para_usuario/2`, acá no hay un "dueño"
que asignar al crear):

- `listar_empresas/0`, `actualizar_empresa/2`, `eliminar_empresa/1`
  (bloqueada si la empresa tiene usuarios — `tiene_usuarios?/1`).
- `listar_branches/1`, `crear_branch/1`, `actualizar_branch/2`,
  `eliminar_branch/1` (bloqueada si la sucursal tiene alguna
  `SalesUnit` o `InventoryLocation` viva — `tiene_hijos_vivos?/3`,
  mismo criterio que `eliminar_empresa/1`). `eliminar_branch/1` **no
  está conectada a ningún botón** en `JerarquiaOrganizacionalLive`
  (ver R9) — existe en el contexto pero no en esta UI.
- `listar_sales_units/1` (por sucursal), `listar_sales_units_de_empresa/1`
  (por empresa completa, usado por el selector de jerarquía operativa
  para un usuario administrador), `crear_sales_unit/1`,
  `actualizar_sales_unit/2`, `eliminar_sales_unit/1` (baja directa, sin
  `tiene_hijos_vivos?` — es hoja).
- `listar_inventory_locations/1`, `listar_inventory_locations_de_empresa/1`,
  `crear_inventory_location/1`, `actualizar_inventory_location/2`,
  `eliminar_inventory_location/1` (idem, baja directa).

## 3. Pantalla — `MetadataAppWeb.Sysadmin.JerarquiaOrganizacionalLive`

`lib/metadata_app_web/live/sysadmin/jerarquia_organizacional_live.ex`,
ruta `/sysadmin/jerarquia` (`router.ex`), permiso
`{"sysadmin_jerarquia", "leer"}` vía
`on_mount {MetadataAppWeb.Hooks.Autorizacion, ...}`.

Layout de 3 columnas, cada nivel condicionado a la selección del nivel
anterior:

1. **Empresas** (columna fija, izquierda) — lista siempre visible;
   ítem "Editar" abre un form inline para `actualizar_empresa/2` (solo
   `nombre`). Sin alta ni baja acá (R5) — eso vive en `EmpresasLive`.
2. **Sucursales** (columna fija, centro) — visible solo con una
   empresa seleccionada; alta (`+ Nueva`) y edición inline, ambas vía
   `crear_branch/1`/`actualizar_branch/2`. Sin baja expuesta (R9).
3. **Unidades de venta / Ubicaciones de inventario** (panel derecho,
   grid de 2 columnas) — visible solo con una sucursal seleccionada;
   alta, edición y baja completas en ambas listas, con `data-confirm`
   antes de eliminar.

Cambiar la empresa seleccionada limpia sucursal/hojas seleccionadas
(`cerrar_branch_seleccionada/1`); cambiar de sucursal recarga ambas
listas de hojas desde cero.

Edición de nombre de Empresa desde esta pantalla es un agregado del
2026-09-11 (mismo `Autenticacion.actualizar_empresa/2` de siempre,
segundo punto de entrada para no saltar de pantalla mientras se edita
el resto de la jerarquía) — la fuente de verdad para alta/baja de
Empresa sigue siendo `EmpresasLive`.

## 4. Navegación y permisos

- Ítem de menú en `menu_layout.ex`, dentro de `@recursos_administrativos`
  (junto a Roles/Empresas/Usuarios/Catálogos de permisos), ícono
  `account_tree`, visible solo si `"sysadmin_jerarquia"` está en
  `@opciones_administrativas` del usuario.
- Permiso/capacidad de Sysadmin `sysadmin_jerarquia` (rol de sistema
  `acceso_sysadmin_jerarquia`), sembrado en
  `priv/repo/migrations/20260816014352_seed_permisos_capacidades_sysadmin.exs`
  y declarado en `MetadataApp.Permissions.capacidades_sysadmin/0`.

## 5. Consumidores de esta jerarquía (fuera de esta spec, solo referencia)

- **Alcance de Datos por usuario** — `usuario_branch`,
  `usuario_sales_unit`, `usuario_inventory_location` (3 tablas N:N),
  alimentan `Scope.branches_permitidos/sales_units_permitidas/
  inventory_locations_permitidas`. Ver `SPEC-SYS-1709202601-sysadmin-
  usuarios` / `SPEC-SYS-1109202605-bc-motor-tab-permisos-alcance`.
- **Unidad Operativa activa en sesión** — `UsuarioLive.SeleccionarJerarquia`,
  `JerarquiaSessionController` (activar empresa/branch/inventory
  location/sales unit) y el modal "Cambiar Unidad Operativa"
  (`cambiar_unidad_operativa_modal.ex`, activa las 4 dimensiones juntas
  en un solo POST).
- **Configuración de Sales Unit (app móvil)** —
  `SPEC-ADN-2209202601-config-sales-unit` referencia `sales_unit_id`/
  las Ubicaciones de inventario ("Almacén") de este mismo catálogo por
  id, sin duplicar el modelo.
