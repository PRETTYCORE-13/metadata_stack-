# SPEC-SYS-0109202601 — Administrador de Folios de Transacciones

**Documento:** Explicación general · **Fase:** ✅ aprobada (2026-09-01).

## ¿Qué problema resuelve?

Cada documento de negocio — una factura, un pedido, una orden de
compra, un vale de almacén — necesita una referencia única e
irrepetible para poder identificarlo, controlarlo y auditarlo. Es el
equivalente digital del "folio" que antes se estampaba en papel con
un sello consecutivo. Sin esa referencia, la única forma de nombrar un
documento sería por cliente+fecha+monto+sucursal, algo ambiguo y poco
práctico — y también la base de cualquier control real contra fraude:
detectar un documento apócrifo, o hacer una "compulsa" (comparar el
papel físico impreso contra lo que quedó registrado en el sistema).
Esta spec construye el motor que asigna esa referencia — Serie +
Folio — de forma automática, única y permanente.

## ¿Cómo funciona, a grandes rasgos?

Un administrador funcional (alguien del negocio con ese permiso, no
necesariamente alguien técnico) configura, para cada tipo de
documento — y sus variantes, por ejemplo una Nota de Crédito o una
Nota de Cargo dentro de Factura — una Serie (un código corto de 4
caracteres) y decide si el conteo es único para todo el sistema o
independiente por sucursal, además de en qué número quiere arrancar a
contar. A partir de ahí, cada vez que alguien — o cualquier sistema
automático, integración o robot — da de alta un documento de ese
tipo, recibe automáticamente el siguiente número consecutivo de esa
Serie, en el mismo instante en que se guarda el documento; nunca lo
elige ni lo escribe a mano. Ese número queda pegado para siempre a ese
documento: aunque el documento se cancele después, su folio nunca se
libera ni se reutiliza en otro. Si dos personas — o dos sistemas —
piden folio exactamente al mismo tiempo, el motor garantiza que cada
uno reciba un número distinto, sin duplicados ni huecos. Todo el
historial de qué folio se asignó, a qué documento y cuándo, queda
disponible para consultarlo en cualquier momento, sin límite hacia
atrás — la base de cualquier compulsa futura. Serie+Folio también
puede consultarse desde la ficha del documento, desde la tabla de
listado (como columna opcional), y desde cualquier integración que
consulte el documento por API — en ningún caso es editable, solo de
lectura.

## Historia

Después de la primera versión aprobada, se agregó una regla extra a
pedido explícito: si la variante de un documento (por ejemplo, un tipo
de Nota de Crédito puntual) está dada de baja, el sistema rechaza
asignarle folio — sin importar desde qué canal se lo pida. Esto trajo
consigo un catálogo nuevo, propio, para manejar el ciclo de vida
Activo/Baja de esas variantes, separado del estado del propio
documento.

## ¿Quién usa esta funcionalidad?

El administrador funcional, que configura los perfiles de numeración
(Serie, granularidad, número inicial) desde una pantalla dedicada
dentro del sistema. El usuario final, que recibe el folio
automáticamente al dar de alta un documento y nunca lo toca a mano.
Y cualquier canal automático — integraciones, API externa, agentes,
scripts — que dé de alta un documento de un tipo que tiene folio
configurado.

## Lo que esta spec NO hace

No define el diseño del documento impreso en sí (la plantilla de la
factura, del vale) — solo genera y entrega la referencia. No permite
ninguna otra forma de agrupar el conteo más allá de "global" o "por
Sucursal" (por ejemplo, no hay folio por caja o por usuario). No
reinicia folios automáticamente (por ejemplo, "cada año vuelve a 1")
— si un cliente necesita reiniciar, un administrador da de alta una
Serie nueva a mano. Y no migra numeraciones ya usadas en otro sistema
anterior (folios "externos") — una necesidad real reconocida, pero
dejada fuera de esta implementación a propósito.
