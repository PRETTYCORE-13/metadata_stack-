# SPEC-SYS-1709202603 — Baja de Sistema

**Documento:** Explicación general · **Fase:** ✅ aprobada (2026-09-21).

## ¿Qué problema resuelve?

Ya teníamos una forma de crear un sistema nuevo desde cero — su base de
datos, su aplicación corriendo, su dirección web propia, todo armado en
un solo paso. Lo que faltaba era lo contrario: una forma segura de
**deshacer** eso mismo cuando un sistema ya no hace falta (por ejemplo,
uno de prueba que cumplió su propósito, o un cliente que se da de baja).

Antes de esta spec, dar de baja un sistema significaba borrar, a mano y
uno por uno, cada pedacito que lo compone: la base de datos, la
aplicación corriendo en el servidor, la dirección web, y el registro
interno que dice "este sistema existe". Nadie confirmaba nada antes de
borrar, y si algo fallaba a mitad de camino, quedaba en el aire sin
forma clara de saber qué faltaba.

## ¿Cómo funciona, a grandes rasgos?

Al pedir la baja de un sistema, primero se saca una **copia completa de
su base de datos** — automática, sin que nadie tenga que acordarse de
pedirla — antes de tocar absolutamente nada más. Es la red de seguridad:
si alguien se equivocó de sistema, o simplemente se arrepiente después,
esos datos no se pierden.

Recién después de guardar esa copia, el sistema pide una
**confirmación explícita**: hay que escribir el nombre exacto del
sistema que se va a borrar. No alcanza con apretar "sí" — tenés que
escribirlo vos mismo, para que un click de más (o copiar y pegar un
comando sin pensarlo) no borre el sistema equivocado por accidente.

Con eso confirmado, se borra todo en orden: la aplicación que corre en
el servidor, la base de datos, la dirección web, y por último el
registro interno que decía que ese sistema existía. Al final, el
mecanismo revisa por su cuenta que efectivamente no haya quedado nada
suelto — ni un pedacito de la aplicación vieja dando vueltas en algún
lado.

Y si algo se corta en el medio (se cae la conexión, falla un servicio
externo), no hay que empezar de nuevo desde cero ni reparar nada a
mano: correr el mismo comando otra vez retoma justo donde había
quedado, sin repetir pasos que ya se hicieron bien.

## ¿Quién usa esto y cuándo?

Lo usa el equipo de Desarrollo cuando un sistema — casi siempre uno de
prueba — ya cumplió su propósito y hay que sacarlo de en medio. No es
algo que pase todos los días, pero cuando pasa, ahora es un solo
comando en vez de una lista de pasos manuales para recordar y no
olvidar ninguno.

## Lo que esta spec NO hace

No decide **cuándo** o **por qué** dar de baja un sistema — esa sigue
siendo una decisión de negocio de cada caso. Tampoco cubre restaurar el
respaldo automáticamente si alguien se arrepiente después: hoy eso es
un procedimiento manual, no un botón. Y no toca los tres canales
internos de prueba (unstable/testing/stable) — esos no son sistemas
dados de alta, viven aparte.
