# SPEC-SYS-1109202603 — BC Motor: Tab Contrato

**Documento:** Explicación general · **Fase:** ✅ aprobada (2026-09-11).

## ¿Qué problema resuelve?

Cuando un catálogo ya está armado (sus campos, sus estados, sus
transiciones), cualquier sistema externo que quiera consumirlo por API
necesita saber qué pedir y qué esperar de vuelta — qué direcciones
existen, qué información hay que mandar, y cómo va a verse la respuesta.
Escribir esa documentación a mano tiene un problema: se desactualiza
apenas alguien cambia algo del catálogo. El tab "Contrato" resuelve
esto generando esa documentación automáticamente, siempre en sincronía
con la configuración real, porque se arma de nuevo en cada visita a
partir de los mismos datos — nunca escrita ni guardada a mano.

## ¿Cómo funciona, a grandes rasgos?

El tab muestra una tarjeta por cada acción posible sobre el catálogo vía
API: consultar el listado completo, consultar un registro puntual, dar
de alta uno nuevo (o varios de una sola vez), y ejecutar cada una de las
transiciones configuradas en el tab Configuración. Cada tarjeta muestra
el método (consultar, crear, modificar...), la dirección exacta, una
explicación en texto simple, y ejemplos armados con datos ficticios pero
realistas — mostrando exactamente los campos reales del catálogo, no un
ejemplo genérico.

Si el catálogo tiene catálogos "detalle" colgando de él (como los
renglones de un pedido colgando del encabezado), el tab también
documenta ahí mismo cómo consultar esos renglones y cómo se arman al dar
de alta o al mover de estado un registro — un catálogo detalle no tiene
su propia pestaña Contrato, toda esa información vive en el Contrato de
su catálogo maestro.

Cuando un catálogo tiene una acción que da de alta un registro nuevo
dentro del flujo de estados, el tab avisa que esa acción corre
automáticamente al crear el registro — nunca aparece como una acción
aparte, porque intentar dispararla por separado siempre fallaría (un
registro recién creado no está en ningún estado todavía).

Si el catálogo todavía no tiene ninguna transición configurada, el tab
lo dice explícitamente en vez de mostrar una sección vacía sin
explicación.

## ¿Quién usa esta funcionalidad?

Principalmente gente técnica (de ADN, de plataforma, o de un equipo
externo) que necesita integrar un sistema con la API de un catálogo
puntual — es la referencia rápida para saber qué pedir y qué esperar,
sin tener que leer código ni pedirle la información a otra persona.

## Lo que esta spec NO hace

No documenta cómo se editan los campos, estados o transiciones que este
tab describe (eso vive en
`SPEC-SYS-1109202601-bc-motor-tab-configuracion`), ni el mecanismo real
de autenticación/autorización de esos endpoints (queda para una spec
propia de la API si hace falta documentarlo). Tampoco documenta el tab
"Permisos" (quién puede ejecutar cada transición), aunque comparte los
mismos datos de catálogo y transiciones.
