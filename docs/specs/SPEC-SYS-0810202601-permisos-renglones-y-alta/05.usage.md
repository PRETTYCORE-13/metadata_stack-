# SPEC-SYS-0810202601 — Permisos de renglones según el estado del documento, y alta solo con campos editables

**Documento:** Guía de uso · Grupos A-F verificados (2026-10-08).

## 1. Objetivo

Que un documento con renglones respete los permisos de su estado actual,
que el alta no acepte datos que no se capturan, y que una referencia mal
puesta dé un mensaje y no un error interno.

## 2. ¿Quién utiliza esta funcionalidad?

- **Quien diseña catálogos:** los permisos de renglones por estado y los
  campos editables por transición funcionan como se configuran.
- **Quien integra por API o importa desde Excel:** recibe el rechazo con
  el campo.
- **El usuario final:** no puede alterar un documento cerrado.

## 3. Conceptos que debo conocer

- **Permisos de renglones** (pestaña Permisos del Motor del maestro):
  por estado, si se pueden insertar, actualizar y borrar renglones.
  **Siempre se revisan con el estado actual del documento.** El estado
  que guarda cada renglón no sigue al documento cuando una transición no
  incluye renglones, así que no se usa para esto.
- **Campos editables del alta:** los que la transición `alta` tiene como
  editables y que el contrato del campo marca editables (igual que en
  `guardar`). Aplica cuando quien da de alta es un usuario (pantalla, API,
  importación); el código del sistema (reglas POST, procesos internos)
  puede poner valores calculados.
- **Renglones nuevos (criterio híbrido):** un campo con "editable: no"
  nunca se acepta. Si la transición del maestro lista campos de ese
  detalle, además el campo debe estar en la lista; si no lista ninguno,
  basta el contrato.

## 4. Mensajes

| Situación | Mensaje |
|---|---|
| Quitar un renglón en un estado sin "borrar" | "En el estado Confirmado no se pueden quitar renglones de Renglones del pedido" |
| Cambiar un renglón en un estado sin "actualizar" | "En el estado Baja no se pueden cambiar renglones de …" |
| Alta con un campo del encabezado que no se captura en el alta | En el campo: "no editable en el alta" (API: 422) |
| Alta o guardar con un renglón que trae un campo no capturable | "Renglón 1 de Renglones del pedido: el campo Total no es editable en el alta" |
| Referencia a un registro que no existe | En el campo: "no existe un registro con este valor" (API: 422) |

## 5. Importación desde Excel

- El asistente ya **no ofrece** campos que no se capturan (por ejemplo,
  los totales del pedido o la fecha de remisión en el alta).
- **Plantillas guardadas antes de esta spec:** si incluyen uno de esos
  campos, sus filas ahora se rechazan con el nombre del campo. Hay que
  editar la plantilla y quitar la columna. En dev, al 2026-10-08, ninguna
  plantilla estaba afectada.

## 6. Limitaciones

- Al configurar un maestro-detalle, conviene listar los campos de los
  renglones en `alta` y `guardar` del maestro: así la transición también
  controla qué se captura en cada renglón (si no los lista, solo cuenta
  el contrato).
- El estado guardado en cada renglón sigue sin sincronizarse con el del
  documento; ya no afecta los permisos.

## 7. Referencias a la SPEC

Requisitos R1-R12 (R5 ajustado); diseño D1-D7 y D3.1; pruebas en
`test/metadata_app/permisos_renglones_y_alta_test.exs`.
