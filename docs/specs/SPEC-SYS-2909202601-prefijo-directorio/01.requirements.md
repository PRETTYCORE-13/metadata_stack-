# SPEC-SYS-2909202601 — Prefijo de directorio

**Documento:** Requirements · **Fase:** ✅ aprobada (2026-09-29).

## 1. Propósito y alcance

Un directorio (carpeta de BC Lista) agrupa los artefactos de un módulo
en el menú. Esta spec le agrega un **prefijo de directorio**: una
abreviatura corta y única del módulo (ej. `CH` para Capital Humano).

Tiene dos partes:

- **§2–§4, prefijo de directorio:** capturarlo, validarlo, editarlo y
  verlo en BC Lista.
- **§5, el directorio viaja completo:** hoy un directorio ya se puede
  publicar desde BC Lista ("Publicar paquete"), pero si ya existe en el
  sistema destino, solo se actualizan su ícono y su orden. Un cambio de
  etiqueta o de visibilidad no llega al destino, y el prefijo tendría
  el mismo problema.

No confundir con el **prefijo del BC** (la abreviatura propia de cada
catálogo, ej. `EMP`) ni con el código combinado (`CH-EMP`): los dos son
un cambio posterior, con su propia spec.

Lo que ya tiene spec propia solo se referencia:

| Tema | Spec |
|---|---|
| Crear, editar, ordenar, eliminar y publicar directorios | SPEC-SYS-2809202601-bc-lista |
| Cómo viaja un artefacto entre ambientes | SPEC-ARQ-2209202602-propagacion-artefactos-negocio |

## 2. Captura

R1. CUANDO se crea un directorio con "+ Carpeta", EL SISTEMA DEBE
pedir el prefijo de directorio junto con la etiqueta, la ruta y el
ícono, y NO DEBE guardar el directorio sin él.

R2. EL SISTEMA DEBE aceptar como prefijo de directorio solo de 1 a 5
letras (A-Z) o dígitos, en mayúsculas.

R3. MIENTRAS el usuario escribe el prefijo de directorio, EL SISTEMA
DEBE corregirlo solo: pasar a mayúsculas, quitar acentos (`Á` → `A`),
eliminar espacios y cualquier otro carácter, y cortar en 5. Ejemplo:
"Cápi tal" → "CAPIT".

## 3. Unicidad

R4. EL SISTEMA NO DEBE permitir que dos directorios activos tengan el
mismo prefijo de directorio, sin importar en qué parte del menú estén.

R5. CUANDO el prefijo escrito ya lo usa otro directorio activo, EL
SISTEMA DEBE avisarlo mientras se escribe, indicando la etiqueta del
directorio que lo tiene, y no guardar.

R6. CUANDO un directorio se elimina, EL SISTEMA DEBE dejar su prefijo
de directorio libre para otro directorio.

R7. SI dos personas guardan al mismo tiempo el mismo prefijo en
directorios distintos, EL SISTEMA DEBE guardar solo uno y mostrarle al
otro el aviso de R5, sin error técnico.

## 4. Edición y directorios existentes

R8. EL SISTEMA DEBE permitir cambiar el prefijo de directorio desde
"Editar carpeta", con las mismas reglas de R2–R5; el directorio que se
está editando no cuenta como "otro" para R4.

R9. Los directorios creados antes de esta spec no tienen prefijo. EL
SISTEMA DEBE seguir mostrándolos, ordenándolos y publicándolos igual
que hoy, y pedir el prefijo la próxima vez que alguien los edite: sin
prefijo, "Editar carpeta" no guarda.

R10. EL SISTEMA NO DEBE mostrar ni pedir el prefijo de directorio al
usuario final de negocio; solo en BC Lista (Sysadmin).

R11. EL SISTEMA DEBE mostrar en el árbol de BC Lista una columna
"Prefijo" con el prefijo de cada directorio. Un directorio sin prefijo
(R9) DEBE mostrarse marcado como "Sin prefijo", para distinguirlo de un
vistazo. Catálogos, Consultas Ecto, SQL Views y carpetas implícitas
(las que no se crearon con "+ Carpeta") dejan la columna vacía.

## 5. El directorio viaja completo

R12. CUANDO se publica un directorio a un sistema donde todavía no
existe, EL SISTEMA DEBE crearlo con todas sus características:
etiqueta, ruta, ícono, visibilidad, orden en el menú y prefijo de
directorio.

R13. CUANDO se publica un directorio que ya existe en el sistema
destino, EL SISTEMA DEBE actualizar ahí su etiqueta, ícono, visibilidad,
orden en el menú y prefijo de directorio a los valores del origen. La
ruta no se actualiza: no es editable (SPEC-SYS-2809202601, R11).

R14. CUANDO se publica un directorio sin prefijo (R9), EL SISTEMA NO
DEBE borrar el prefijo que ese directorio ya tenga en el destino.

R15. SI el prefijo de directorio que llega ya lo usa otro directorio
distinto en el sistema destino, EL SISTEMA DEBE aplicar el resto de las
características del directorio (R13), dejar su prefijo en el destino
como estaba, y registrar en el resultado del despliegue un aviso que
indique qué directorio del destino tiene ese prefijo. **Corregido
2026-09-29** (antes decía "detener la publicación"): el destino importa
los artefactos al arrancar su nueva versión, cuando la publicación ya
ocurrió, y esa importación es tolerante a propósito para que un
artefacto con problemas no deje caído el sistema.

## 6. Fuera de alcance

- El prefijo del BC y el código combinado (`CH-EMP`): cambio posterior.
- Usar el prefijo de directorio en algún lado (menú, códigos, folios,
  reportes).
- Prefijo en catálogos, Consultas Ecto o SQL Views.
- Cambiar la ruta de un directorio al publicar.
