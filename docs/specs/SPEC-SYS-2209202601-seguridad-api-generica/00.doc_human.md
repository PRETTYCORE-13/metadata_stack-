# SPEC-SYS-2209202601 — Seguridad real en la API genérica (`/api`)

## ¿Qué problema resuelve?

Hoy, la API que expone cada catálogo del sistema (`/api/<catalogo>`, crear/
editar/borrar registros, ejecutar transiciones de estado, e incluso definir
catálogos nuevos o borrarlos por completo) no tiene ninguna protección real:
cualquiera que encuentre la URL puede leer y modificar datos, o incluso
borrar un catálogo entero, sin haber iniciado sesión. Es una brecha de
seguridad real en un sistema que ya está desplegado.

Esta spec cierra esa brecha reusando el mecanismo de permisos que YA existe
y ya protege la pantalla web equivalente (roles, permisos por catálogo) —
no inventa nada nuevo, solo conecta lo que falta.

## ¿Cómo funciona, a grandes rasgos?

Cada request a esta API pasa primero por dos preguntas, en orden:

1. **¿Quién sos?** Si no hay una sesión iniciada, la respuesta es un
   rechazo claro (401) — ni siquiera se mira qué se pidió.
2. **¿Te corresponde hacer esto?** Con sesión válida, se verifica el mismo
   permiso que ya existe para la pantalla web (leer/crear/editar/eliminar
   sobre ESE catálogo puntual, o el permiso de plataforma que corresponda
   para acciones administrativas como crear un catálogo nuevo). Sin ese
   permiso, la respuesta es un rechazo claro (403).

Un administrador de la plataforma (rol "administrador") sigue teniendo
acceso a todo, igual que ya pasa en la web — esta spec no le agrega
restricciones a quien ya podía hacer cualquier cosa.

## ¿Quién usa esta funcionalidad?

Nadie la "usa" directamente — es una capa de protección transparente para
cualquier sistema externo o interno que consuma la API genérica de
catálogos. Un integrador que ya mandaba sus requests con una sesión válida
y los permisos correctos no nota ningún cambio; alguien sin login o sin el
permiso correspondiente empieza a recibir un rechazo claro en vez de acceso
silencioso.

## Lo que esta spec NO hace

No toca la API de Endpoints por Consulta (`/api/consultas/*`,
`SPEC-SYS-1009202602`), que ya tiene su propio mecanismo de API key —
esta spec es exclusivamente sobre la API genérica de catálogos (`/api/
<catalogo>` y afines). Tampoco cambia el modelo de permisos en sí (qué
roles existen, cómo se conceden) — solo conecta el chequeo que ya existe
a rutas que hoy no lo tienen.
