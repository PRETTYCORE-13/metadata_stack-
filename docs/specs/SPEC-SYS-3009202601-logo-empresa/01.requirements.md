# SPEC-SYS-3009202601 — Logo de empresa

**Documento:** Requirements · **Fase:** ✅ aprobada (2026-09-30).

## 1. Propósito y alcance

Cada empresa (tenant, `meta_schema_empresa`) puede tener un **logo**
propio que se muestra en miniatura en la top bar del layout
(`pc-topbar-brand`, a la izquierda de `pc-topbar-empresa`), para
identificar al cliente de un vistazo y no solo por la URL o el texto
del nombre.

Tiene tres partes:

- **§2, captura:** subir, cambiar y quitar el logo desde
  `/sysadmin/empresas`.
- **§3, visualización:** mostrarlo en la top bar sin deformarla nunca.
- **§4, performance:** que mostrar el logo no agregue costo por request
  ni por navegación.

Fuera de alcance: el logo del sistema en la barra lateral
(`pc-sidebar-logo`), el favicon, y usar el logo en reportes o PDFs
(eso sería otra spec que puede reusar este mismo logo).

## 2. Captura

R1. EL SISTEMA DEBE permitir subir un logo a una empresa desde el modal
"Editar" de `/sysadmin/empresas`, con el mismo permiso que hoy permite
renombrarla.

R2. EL SISTEMA DEBE aceptar solo imágenes **PNG, JPEG, WebP o GIF**,
reconociendo el formato por el contenido real del archivo (sus primeros
bytes), no por la extensión del nombre.

R3. EL SISTEMA NO DEBE aceptar SVG ni ningún otro formato. Motivo: un
SVG puede llevar código ejecutable y servirse desde el mismo dominio
del sistema.

R4. EL SISTEMA NO DEBE aceptar un archivo de más de **200 KB**, y DEBE
avisarlo antes de subirlo, sin error técnico.

R5. EL SISTEMA DEBE mostrar junto al campo de carga la recomendación:
"PNG o WebP con fondo transparente, horizontal, 320 × 64 px (proporción
5:1), máximo 200 KB".

R6. CUANDO se elige un archivo, EL SISTEMA DEBE mostrar una vista previa
del logo con el mismo tamaño y recorte que tendrá en la top bar (R9),
antes de guardar.

R7. CUANDO la imagen elegida no es horizontal o se sale de la
proporción recomendada (menor a 2:1 o mayor a 6:1), EL SISTEMA DEBE
mostrar un aviso ("se verá más chica de lo ideal") pero DEBE permitir
guardarla igual.

R8. EL SISTEMA DEBE permitir **cambiar** el logo por otro y **quitarlo**.
Al quitarlo, la top bar vuelve a mostrar solo el nombre.

## 3. Visualización en la top bar

R9. MIENTRAS la empresa activa de la sesión tiene logo, EL SISTEMA DEBE
mostrarlo en la top bar a la izquierda del nombre de la empresa, dentro
de un espacio fijo de **32 px de alto y hasta 160 px de ancho**,
respetando siempre su proporción original (nunca estirado ni aplastado).

R10. EL SISTEMA NO DEBE cambiar la altura de la top bar por tener o no
logo, ni por la forma o tamaño de la imagen.

R11. MIENTRAS la empresa activa no tiene logo, EL SISTEMA DEBE mostrar
la top bar exactamente como hoy (solo el nombre).

R12. EL SISTEMA DEBE mostrar el logo legible en tema claro y en tema
oscuro (un logo oscuro con fondo transparente no debe desaparecer en
tema oscuro).

R13. CUANDO el usuario cambia de empresa activa, EL SISTEMA DEBE mostrar
el logo de la nueva empresa (o ninguno, si no tiene).

R14. En pantallas de celular, EL SISTEMA DEBE seguir mostrando el logo
sin empujar la campana ni el usuario fuera de la barra; si no hay
espacio, el nombre de la empresa se recorta con "…" antes que el logo.

## 4. Performance y escalabilidad

R15. EL SISTEMA NO DEBE leer el contenido de la imagen al armar la
sesión ni al pintar cada pantalla: la top bar solo necesita saber si hay
logo y cuál versión es.

R16. EL SISTEMA DEBE permitir que el navegador guarde el logo en caché
de forma permanente, de modo que al navegar entre pantallas no se vuelva
a descargar; CUANDO el logo cambia, EL SISTEMA DEBE mostrar el nuevo sin
que el usuario tenga que limpiar la caché.

R17. EL SISTEMA DEBE servir el logo igual desde cualquier réplica del
sistema (varios pods en k3s), sin depender del disco de un pod en
particular, y sin perderlo en un redeploy.

R18. EL SISTEMA DEBE servir el logo solo a usuarios con sesión iniciada
que pertenecen a esa empresa.

## 5. Datos y ambientes

R19. El logo es un dato de la empresa, no metadata: EL SISTEMA NO DEBE
incluirlo en exportaciones/publicaciones de metadata entre ambientes
(Tepache, `mix motor.publicar`, propagación).

R20. CUANDO una empresa se da de baja, EL SISTEMA DEBE dejar de servir
su logo.
