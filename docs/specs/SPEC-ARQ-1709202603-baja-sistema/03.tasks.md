## Nota — hallazgo de infraestructura, fuera del alcance formal de esta spec

**Bug real en `MetadataApp.Ssh`, encontrado investigando por qué la
restauración de la tarea 13 se colgaba** (no relacionado al bug real de
esa restauración en sí): `cat archivo_grande.sql | ssh host "kubectl
exec -i ... -- psql ..."` se cuelga para siempre si el proceso remoto
(`psql`) termina rápido con error antes de consumir todo el stdin que
`cat` le sigue mandando — `kubectl exec -i` no siempre detecta que el
proceso remoto ya murió. Se colgó más de una hora, dos veces seguidas,
sin ningún error de por medio. Corregido con un wrapper `timeout -k 10`
en `Ssh.correr/5` (nuevo parámetro `timeout_segundos`, default 180s) —
cubre esto y cualquier otro cuelgue futuro, sin importar la causa.
Combinado con el fix real y distinto que el equipo ya había encontrado
el mismo día para Windows nativo (`binario_ssh/0`, MSYS2 colgándose al
ser lanzado por un proceso Win32 sin consola) — ambos arreglos conviven
en `Ssh.correr/5`, cada uno cubriendo un caso real distinto.
