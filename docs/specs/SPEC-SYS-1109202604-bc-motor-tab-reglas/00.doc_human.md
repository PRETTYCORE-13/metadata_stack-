# SPEC-SYS-1109202604 — BC Motor: Tab Reglas

**Documento:** Explicación general · **Fase:** ✅ aprobada (2026-09-11).

## ¿Qué problema resuelve?

Cada catálogo puede tener lógica de negocio propia que corre en dos
momentos puntuales: justo antes de aplicar un cambio de estado (por
ejemplo, antes de "Aprobar" un documento) y justo después de
aplicarlo. Esa lógica no es un simple casillero de configuración —
es código real, escrito en el mismo lenguaje del sistema (Elixir). El
tab "Reglas" (dentro del Motor BC, al editar un catálogo) es donde ese
código se escribe, se guarda y se pone en marcha, sin salir de la
pantalla ni tocar una terminal.

## ¿Cómo funciona, a grandes rasgos?

Reglas separa el código en dos bloques independientes: "PRE" (corre
antes de aplicar la transición — si algo ahí falla, se frena todo
antes de tocar nada) y "POST" (corre después de aplicarla — si algo
ahí falla, se deshace todo lo que se había hecho). Cada bloque tiene
su propio espacio de edición y se guarda por separado, aunque un solo
botón "Compilar" procesa ambos de una vez.

Un catálogo que todavía no tiene código propio no arranca de una
pantalla en blanco — se le ofrece un esqueleto ya armado, listo para
compilar, con un aviso visible de "todavía sin completar" hasta que
alguien lo reemplace por lógica real.

"Compilar" hace dos cosas en un solo paso: primero valida que el texto
sea código válido (si no lo es, avisa el error exacto y no guarda
nada), y si es válido, lo guarda siempre — aunque después la
compilación en sí falle por otro motivo, el texto ya quedó a salvo.
El sistema también avisa cuando lo guardado en la base y lo que
realmente está corriendo en memoria no coinciden todavía, para que
nadie asuma que un guardado exitoso ya cambió el comportamiento real.

Como red de seguridad extra, si alguien edita un bloque y trata de
salir sin guardar (cerrar la pestaña, recargar, o navegar a otra
pantalla), el sistema avisa antes de perder ese cambio.

Esta edición en vivo solo está disponible en los ambientes de
desarrollo y prueba — en producción, el código se ve pero no se puede
tocar desde acá; llegar ahí es a través del camino normal de
control de versiones y despliegue.

## ¿Quién usa esta funcionalidad?

Gente de ADN o del equipo de plataforma, al construir o ajustar la
lógica de negocio de un catálogo desde el Motor BC — nunca el usuario
final, que solo experimenta el resultado (la transición se aplica o
se rechaza según esa lógica).

## Lo que esta spec NO hace

No documenta cómo el motor de estados invoca esta lógica en cada
transición real, ni la convención de nombres que usa para encontrar el
módulo correcto — eso es comportamiento del motor, no de este tab de
edición. Tampoco cubre el botón "Compila Todo" de la cabecera del BC
Motor (recompila tabla + reglas juntas), que es una acción global del
Motor BC, no algo propio de este tab.
