# SPEC-SYS-0810202603 — Cálculo preliminar del renglón al capturar

**Documento:** Requirements · **Fase:** ✅ aprobada (2026-10-08).

**Origen:** paso B del precio por renglón del pedido
(SPEC-ADN-0710202601); el paso A es SPEC-SYS-0810202602 (columnas de
solo lectura).

## 1. La pregunta a las reglas

R1. EL SISTEMA DEBE permitir que las reglas de un catálogo maestro
respondan, de forma opcional, el cálculo preliminar de un renglón de
uno de sus detalles: recibe el nombre del detalle, los valores del
encabezado (lo capturado en pantalla, guardado o no) y los valores del
renglón, y responde los valores calculados del renglón, que no hay
nada que calcular, o un aviso.

R2. SI las reglas del maestro no responden esa pregunta, EL SISTEMA
DEBE comportarse exactamente como hoy.

R3. EL SISTEMA DEBE aceptar en la respuesta solo campos de solo
lectura de ese detalle (SPEC-SYS-0810202602); cualquier otro campo se
ignora. El cálculo preliminar nunca cambia lo que el usuario capturó.

## 2. Cuándo se calcula

R4. CUANDO el usuario cambie un campo de un renglón desde el formulario
de captura (renglón nuevo o ya guardado), EL SISTEMA DEBE pedir el
cálculo preliminar de ese renglón.

R5. EL SISTEMA DEBE esperar a que el usuario deje de escribir (unos
300 ms) antes de pedir el cálculo, para no hacer una consulta por
tecla.

R6. SI el renglón todavía no tiene los datos que las reglas necesitan
(por ejemplo, falta la cantidad o la dirección del encabezado), las
reglas DEBEN poder responder "nada que calcular", y EL SISTEMA DEBE
dejar vacías las columnas calculadas de ese renglón.

## 3. Cómo se ve

R7. EL SISTEMA DEBE mostrar los valores preliminares en las columnas de
solo lectura del renglón, distinguidos de los definitivos (por ejemplo,
en cursiva) y con la leyenda "preliminar" al pasar el cursor.

R8. SI las reglas responden un aviso, EL SISTEMA DEBE mostrarlo junto
al formulario de captura, sin bloquear la captura ni el botón Guardar.

R9. Al guardar (o con "Actualizar ficha"), la tabla DEBE mostrar los
valores definitivos que calculó el sistema, ya sin la marca de
preliminar.

## 4. Lo que no cambia

R10. Los valores preliminares NUNCA DEBEN viajar al guardar ni
guardarse (ya lo garantiza SPEC-SYS-0810202602, R4).

R11. Si el cálculo preliminar falla por un error inesperado de las
reglas, EL SISTEMA DEBE registrar el error y seguir como si no hubiera
respuesta, sin tirar la pantalla.

## 5. Fuera de alcance

- Totales del encabezado en vivo.
- Recalcular los renglones al cambiar el encabezado.
- Renglones pegados en bloque o importados.
- La respuesta del pedido en sí (va en SPEC-ADN-0710202601).
