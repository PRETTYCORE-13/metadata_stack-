# SPEC-SYS-0909202604 — Importación actualiza registros existentes

**Documento:** Explicación general · **Fase:** ✅ aprobada (2026-09-09).

## ¿Qué problema resuelve?

Hoy, cuando alguien importa un archivo de Excel para cargar datos en un
catálogo, el sistema solo sabe dar de alta: cada fila del Excel se
convierte siempre en un registro nuevo. Si una fila coincide con un
registro que ya existe, dos cosas pueden pasar, y ninguna es buena: si
el catálogo tiene una regla de "no repetir este valor", la fila se
rechaza como error; si no la tiene, se crea un duplicado. No hay forma
de decir "esta fila en realidad es una actualización de algo que ya
tengo cargado".

Esta spec agrega ese camino que faltaba: definir un campo que sirva de
identificador (por ejemplo, un folio o un código de producto) para que,
cuando el valor de una fila coincida con un registro existente, ese
registro se actualice en vez de duplicarse o rechazarse.

## ¿Cómo funciona, a grandes rasgos?

Al armar una plantilla de importación, ahora se puede elegir un campo
identificador — tanto para la hoja principal (el "encabezado") como
para cada hoja de detalle que tenga activada (por ejemplo, los
renglones de un pedido). Al importar un archivo con esa plantilla, cada
fila se revisa: si su identificador coincide con un registro existente,
se actualiza; si no coincide con ninguno, se crea uno nuevo, igual que
antes. Si coincide con más de uno a la vez, esa fila se rechaza con un
error, porque no hay forma de saber cuál de los dos actualizar.

Actualizar un renglón de detalle que ya existe sigue las mismas reglas
que ya rigen la edición manual de un registro (las del motor de
estados) — si el catálogo no tiene configurada la transición que
habilita esa edición, la fila se rechaza con un mensaje claro en vez de
fallar en silencio o forzar el cambio por una vía que la edición manual
no permitiría. Agregar un renglón nuevo a un encabezado existente, en
cambio, no depende de esa regla. Antes de confirmar cualquier
importación, la previsualización muestra fila por fila si el resultado
va a ser una creación o una actualización, para que quien importa sepa
el impacto antes de confirmar.

## Historia

La primera versión de esta spec planteaba que actualizar un encabezado
reemplazara TODOS sus renglones por los del archivo nuevo — es decir,
que un renglón viejo ausente del Excel se borrara solo. Se corrigió a
pedido explícito apenas se detectó el riesgo real: un encabezado con 20
renglones donde solo se quiere actualizar 1 habría perdido los otros 19
sin que nadie lo pidiera. La versión final nunca borra un renglón
existente por el solo hecho de no aparecer en el archivo — cada
renglón se actualiza o se crea de forma individual.

## ¿Quién usa esta funcionalidad?

Cualquier persona que importe datos por Excel a un catálogo que tenga
una plantilla de importación con el campo identificador configurado —
uso habitual de negocio, no exclusivo de un rol técnico. Configurar
CUÁL es el campo identificador de cada plantilla sí lo hace quien arma
esa plantilla (típicamente ADN o el equipo de plataforma).

## Lo que esta spec NO hace

No agrega un borrado masivo de renglones ausentes del archivo — si hace
falta eliminar renglones existentes en bloque, eso queda fuera de
alcance y se resuelve por otro medio. Tampoco cambia ninguna regla de
edición ya existente del motor de estados: la importación reutiliza
esas reglas tal cual están, nunca crea un camino nuevo que las evite.
Y no extiende esta actualización a ningún otro origen de datos fuera
de la importación por Excel (por ejemplo, una API).
